# Taste
- Prefers a strict, confirmation-gated step-by-step workflow: build ONLY the step requested, never jump ahead or pre-build future sections, and stop after each step to wait for an explicit "CONFIRMED" / "NEXT" before continuing. Confidence: 0.95
- Wants each step to end with a fixed report format: a 3–5 bullet summary, a list of files created/changed, preview instructions, then a stop. Confidence: 0.9
- Prefers being asked ONE short clarifying question when something is ambiguous rather than having the agent guess. Confidence: 0.85
- Expects previously confirmed work to be left intact — no rewriting or restructuring unless explicitly asked. Confidence: 0.9
- Strongly dislikes invented content: never fabricate facts, statistics, testimonials, addresses, phone numbers, or links; use only the content provided. Confidence: 0.9
- Prefers Next.js (App Router) with TypeScript in strict mode and Tailwind CSS for styling. Confidence: 0.85
- Prefers minimal dependencies: wants to approve adding libraries (e.g., Framer Motion) and favors plain CSS animations otherwise. Confidence: 0.85
- Prefers React Server Components by default, using "use client" only where strictly necessary. Confidence: 0.8
- Wants all copy and links centralized in one typed data file, keeping components free of hard-coded content. Confidence: 0.85
- Prefers mobile-first, fully responsive design that looks polished across the full range (360px to 1440px+). Confidence: 0.8
- Enforces strict code quality: no `any`, no console logs, no unused code, clean folder structure, small reusable components, and zero ESLint/TypeScript errors. Confidence: 0.85
- Favors respecting `prefers-reduced-motion` for any animation. Confidence: 0.75
- Prioritizes accessibility: WCAG AA contrast, visible focus states, full keyboard navigation, a skip-to-content link, and touch targets of at least 44px. Confidence: 0.85
- Prioritizes technical SEO: semantic landmarks, exactly one `<h1>`, logical heading hierarchy, the Next.js Metadata API, JSON-LD structured data, sitemap/robots, and a target of Lighthouse 95+. Confidence: 0.8
- Wants user-supplied copy preserved verbatim rather than silently reworded or "improved"; if a change is made (e.g., fixing an obvious typo) it should be called out explicitly for approval. Confidence: 0.6
- When new feedback arrives mid-step, expects only that specific change to be made, then a stop (no continuing the original step), with a clear note that the interrupted step is paused and how to resume it. Confidence: 0.7
- When supplying an element/idea, also wants the agent to contribute its own original addition alongside it rather than only implementing exactly what was given. Confidence: 0.65
- Declines having the session model switched mid-task, even when a different model would unblock a tool; prefers to work around the limitation (e.g. describing the needed input in text) rather than run a command that changes the model. Confidence: 0.55
- Communicates in terse, lowercase, punctuation-light instructions (e.g. "i add 2 image , justice and bd , add those two image in card 1 and card 7 top"; "in Business Portfolio cards , make the middle card a little bit down and make its bg b3e634") — reads them as complete briefs and expects the agent to infer the rest from the existing code/design rather than ask for a spec. Confidence: 0.7
- Gives subjective design quantities ("a little bit down") and raw, un-prefixed hex codes (e.g. "b3e634") without a unit or token name, expecting the agent to pick the concrete value (px/token) itself. Confidence: 0.6
- Likes a design rhythm where one card in a grid is singled out as an accent-colored (lime #B3E634) "highlight" card, optionally dropped/staggered relative to its neighbors. Confidence: 0.5
- Prefers user-supplied imagery blended/faded into the surface it sits on (soft gradient into the card, no hard-edged frame) rather than presented as a boxed image. Confidence: 0.55
- Reacts to sections that read as empty/plain and wants them filled with subtle layered background decoration (soft accent glows, faint dot grids, low-opacity logo/watermark) rather than leaving a flat surface (e.g. "add some bg elements, its looks empty" for the Portfolio section, then "in core value bg, add the dot bg"). Such decorations should stay behind content and never hurt accessibility. Confidence: 0.6
- Reversed course on supplied image assets for decorative textures: after the agent had wired a dropped file as `bg-[url(/bg.png)] bg-repeat`, he rejected that and told the agent to revert it and "do not use the bg.png image" — the texture should be authored by the agent itself in CSS (e.g. a `radial-gradient` dot layer via arbitrary Tailwind properties) rather than referencing a raster file. Confidence: 0.6
- Wants statement typography for slogan/headline moments to be light and elegant, not bold or gimmicky: on seeing the repeated-outline/echo treatment applied to the closing slogans he rejected it outright ("no , i dont like it , write those using light fancy text") and settled on a light-weight serif (Cormorant Garamond 300) at a large display size. Reads "fancy" as a typeface choice and is happy for a decorative display face (added via next/font) to be introduced for it. Confidence: 0.7
